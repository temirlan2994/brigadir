## [ПОДТВЕРЖДЕНО] RecordCard.tsx:112 — Заметка в карточке записи сохраняется только по onBlur и теряется при системном «Назад»
Поле заметки — неуправляемый input с defaultValue, сохранение только в onBlur (строка 112). На телефоне blur при уходе с экрана НЕ срабатывает: (1) Android/TWA — первая системная «Назад» закрывает клавиатуру, НЕ снимая фокус с поля; вторая «Назад» навигирует, React размонтирует компонент, а при удалении сфокусированного элемента из DOM браузеры не шлют blur/focusout → patch({note}) не вызывается, текст молча пропадает; (2) iOS Safari — свайп-назад даёт тот же unmount без blur; (3) сворачивание/убийство приложения с открытой клавиатурой. Внутренняя кнопка «Назад» в шапке случайно работает (тап по кнопке сначала даёт blur), поэтому при тестировании пальцем на своей навигации баг не виден. Исправление: сохранять в onChange (можно с debounce ~500мс), onBlur оставить как финальный trim; либо перевести на управляемый state + сохранение и в onChange, и в onBlur.

## [ПОДТВЕРЖДЕНО] ActPrint.tsx:83 — «Распечатать акт» — window.print() мёртв в установленном приложении
Единственное действие экрана «Акт» — BigButton с onClick={() => window.print()} (ActPrint.tsx:83). Манифест собирается с display: 'standalone' (vite.config.ts:34). В iOS standalone (приложение с экрана «Домой») window.print() — документированный no-op: диалога печати в standalone-режиме у WebKit нет, тап не делает ничего. В Android TWA печать из Trusted Web Activity тоже давно сломана/ненадёжна в Chromium. То есть именно на телефоне, куда приложение ставится, кнопка выглядит рабочей, но молчит. Обход: вместо window.print() формировать файл и отдавать через navigator.share({files:[...]}) (работает в standalone iOS/Android), а window.print() оставить фолбэком, когда navigator.share недоступен; минимум — показывать toast «Откройте в браузере, чтобы распечатать», когда matchMedia('(display-mode: standalone)') истинно.
