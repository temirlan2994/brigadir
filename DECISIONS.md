# Решения по ходу разработки

- HashRouter вместо BrowserRouter — чтобы приложение работало на любом статическом хостинге (GitHub Pages) и офлайн без настройки переадресаций.
- splitShares: метод наибольших остатков, при равных остатках тыйын первым в списке — только так сходятся контрольные примеры ТЗ (10/10/5/5 → 33 333,33/16 666,67; 1/1/1 → 33,34 первому).
- «Мне должны» на главной считается по активному объекту; «Я должен рабочим», касса и «Свободно» — по всем объектам (деньги и бригада у подрядчика общие).
- Фазы 0–3 собраны одним заходом (ядро → слой данных → все экраны), коммиты разбиты по смыслу: каркас+ядро, экраны.
- Демо-данные задают начальный остаток кассы 150 000 сом — иначе «Свободно» не сделать положительным при честных цифрах выдач.
- В таблицах настроек (расценки, налог, касса) число редактируется тем же нампадом (с 0.7.0 — прямо в поле, без нижнего листа) — правило «числа только нампадом» соблюдено без громоздких форм.
- Размеры площади (длина/высота/проёмы) и ручные суммы деления вводятся общим нампадом через выбор активного поля-чипа.
- Иконки PWA сгенерированы своим PNG-энкодером на node:zlib (без внешних зависимостей): каска на оранжевом фоне.
- Экспорт CSV: суммы в сомах с запятой («16666,67») — Excel с русской локалью понимает сразу.
- Правка выдач/расходов/поступлений/корректировок — на месте (без версий): по модели данных версии есть только у записей работ.
- Названия видов работ на кыргызском в seed — черновой перевод, помечены к пересмотру: «Кыш кынуу» (кладка), «Шыбоо» (штукатурка), «Кара жумушчу» (разнорабочий), «Чатыр жабуу» (кровля).
- Деплой — GitHub Pages: бесплатно, но репозиторий обязан быть публичным; base /brigadir/ подставляется только в CI (BASE_PATH), локально всё работает от корня.
- Обновления — vite-plugin-pwa в режиме prompt: баннер «Вышло обновление» с кнопкой вместо тихой перезагрузки; проверка при запуске и раз в час.
- APK собран PWABuilder-ом (TWA поверх опубликованного сайта), выложен в GitHub Releases. Ключ подписи и пароли — только локально в android/ (папка в .gitignore). assetlinks.json размещён в отдельном репозитории temirlan2994.github.io, потому что Android проверяет его на корне домена, а не под /brigadir/.
- e2e в CI не гоняем (нужны браузеры Playwright, долго) — только typecheck, lint, юнит-тесты и сборка; e2e остаются локальной проверкой перед пушем.
- «Нативное» поведение в TWA: вкладки не копят историю (replace + схлопывание до корня), шаги мастера лежат в адресе (?step=N) — системный «Назад» ходит по шагам и не стирает черновик; pull-to-refresh и масштабирование выключены; поле ввода закреплено над нампадом (NumPadPanel), чтобы не крутить экран.

## Версия 2 — интерфейс вдоль пути бригадира (22 октября)

- Вкладки «Сегодня · Объекты · Бригада · Касса» вместо «Главная · Работы · Рабочие · Деньги»: журнал работ живёт внутри объекта, деньги заказчика — тоже; касса — общая на все объекты.
- Настройки программы и настройки объекта разведены: в шестерёнке только язык, налог, остаток кассы, справочник работ, копия, обновления. Цены, заказчик, архив и закрытие — внутри объекта.
- Новый объект создаётся мастером из трёх шагов (объект → цены → бригада), он же — первый запуск. Расценки создаются только для отмеченных видов работ; остальные — «—», заполняются по ходу.
- Стадия объекта считается по данным (есть записи → работаем, есть принятое → сдаём, есть поступления → получаем), руками ставится только «закрыл».
- Частичная приёмка: у записи хранится принятый объём и сумма; «принято» и «не сдано» считаются по ним, в акт идёт принятая часть. Остаток остаётся в списке «не принято».
- Аванс заказчика — обычное поступление с признаком kind:'advance'; если поступило больше принятого, показывается «аванс: отработать N», а не «переплатил».
- «Взял себе» / «Вложил свои» — отдельная таблица cashMoves, входит только в кассу (не в прибыль объекта).
- «Кто вышел» — таблица attendance по объекту и дню; подставляет бригаду в мастер записи. Полного табеля нет.
- Итог закрытого объекта считается по факту денег: заплатил заказчик − начислено бригаде − расходы − налог. До закрытия показывается прогноз по выполненному.
- Режим «показать заказчику» прячет цены бригады и прибыль — состояние в памяти, сбрасывается при перезапуске.
- Вечернее напоминание — только подсказка внутри приложения после 18:00; настоящие push без сервера в PWA невозможны.
- Ярлыки «Записать работу» и «Выдал» на долгое нажатие иконки — через shortcuts в манифесте.
- Демо-данные дополнены закрытым объектом «Склад, Кант» (итог +16 000), поэтому касса демо стала 164 500.
## Версия 0.6.0 — бригадиры и ночной батч исправлений (23 октября)

- Самат — подрядчик и управляет бригадирами, а не рабочими поимённо: сущность Worker стала «бригадиром» с полем headcount (сколько человек в его бригаде); деньги по-прежнему делятся между бригадирами. Поимённый список людей внутри бригады не ведём.
- Любая запись истории правится в два касания: строки истории в карточке бригадира кликабельны, в карточке записи — «Изменить сумму», тип, способ, дата и заметка (сохраняется на лету).
- Все находки аудита интерфейса исправлены — список и способы в AUDIT-TODO.md.
- Выгрузка CSV — один файл с разделами (мобильные браузеры режут несколько скачиваний на тап); в установленном приложении файлы уходят через системное «Поделиться».
- Акт на телефоне отправляется текстом; печать — только в браузере.

- По итогам ревью (23 агента): правка записи переносит поля частичной приёмки в новую версию; закрытый или архивный объект никогда не бывает «текущим» — если открытых нет, «Сегодня» предлагает взять объект; налог закрытого объекта заморожен датой закрытия, а для факта процент берётся от полученных денег, не от выполненного; «Отменить» после приёмки остатка возвращает частичную приёмку; перекличка и мастер ждут загрузки данных прежде чем подставлять бригаду.

## Версия 0.7.0 — заказчики-контрагенты, телефон с кодом страны, блок оплаты, цифры прямо в поле (22 октября)

- Цифры печатаются прямо в поле. Одна нампад-клавиатура на всё приложение (KeypadHost) выезжает снизу без своего «табло»; активное поле подсвечено, с мигающим курсором. Старое значение сначала выделено — первая цифра заменяет его, повторный тап по полю — дописать. «Дальше» переходит к следующему числовому полю на экране. Высота клавиатуры уходит в CSS-переменную --kb-h: страница получает отступ снизу, шторки поднимаются над клавиатурой, поле прокручивается выше неё. Экраны сумм (выдал, получил, потратил…) показывают сумму крупным полем сверху, нампад — внизу.
- Системная клавиатура только для текста и телефона. Телефон — type="tel": на телефоне это и так цифровая клавиатура, а автозаполнение и вставка работают как привыкли.
- Телефон: флаг и код страны слева (+996 по умолчанию), номер пишется сразу после кода и делится на группы. Тап по флагу — выбор страны (17 стран: свои, соседи, куда ездят на заработки). Хранится как +996555123456. Вставка целого номера («0555…», «+7 701…», «8 701…», «996…») разбирается и сама выбирает страну; +7 делится на Казахстан (6xx, 7xx) и Россию. Флаги — SVG из flag-icons (MIT), лежат в проекте, работают офлайн.
- Кнопка «из контактов» — Contact Picker API: есть в Chrome на Android и в установленном APK; на iPhone браузер этого не умеет, кнопку там не показываем.
- Контрагенты — отдельная таблица (Dexie v3): компания или частное лицо, кто на связи, телефон, ИНН, адрес, заметка. В объекте хранится ссылка и снимок имени/телефона (customerName/customerPhone), который обновляется при правке контрагента — так акты, отчёты и списки читают заказчика без лишних запросов. Старые заказчики-текст переносятся в контрагентов при запуске (и после загрузки старой копии); одинаковые имена — один контрагент.
- Блок «Как платит заказчик» вместо поля «Как платит» и «Аванс при старте»: «За объёмы» (смета не обязательна, аванс — нет / в % от сметы / суммой, как часто платит по актам) или «Общая сумма» (сумма договора делится на части в процентах или суммами, быстрые варианты 30/70, 30/40/30, 50/50, 4×25, у каждой части — «сразу», «после этапа» или «к дате»). Разбивка обязана сходиться с суммой договора — иначе «Дальше» закрыт и есть кнопка «Добавить разницу в последнюю часть». Суммы из процентов делятся методом наибольших остатков до сома, части в сумме всегда дают ровно договор.
- По общей сумме «заказчик должен» = наступившие части (аванс сразу, этапы — после «Этап сдан», датированные — с даты) − полученное − удержания. Объёмы для таких объектов не принимают: «Сдача заказчику» показывает этапы, акт собирается по сданным этапам. Прогноз прибыли — от суммы договора. По объёмам всё считается как раньше.
- Полученные деньги закрывают части графика по порядку (сначала аванс). В «Получил» подсказка «Ждём: Коробка — 480 000 сом» вставляет сумму и тип одним тапом.
- Мастер нового объекта — 4 шага: объект и заказчик → как платит → цены → бригадиры (с численностью). «Цены и заказчик» внутри объекта разделены на «Заказчик и оплата» (с автосохранением) и «Цены за работы».
- Демо дополнено частным домом за общую сумму (1 200 000, 30/40/30, аванс получен), поэтому «свободно» в демо стало 457 250.

## Версия 0.7.1 — исправления по независимому ревью 0.7.0 (23 октября)

- Номер, набранный по цифре, разбирается так же, как вставленный: ведущий «0» (0555…) отбрасывается, повтор кода страны («996…») и «8» России/Казахстана убираются, когда цифр больше, чем в номере.
- Международный номер с кодом не из списка (+48…) больше не превращается в +996: хранится как набран («+» и цифры), показывается как есть, в WhatsApp и звонок уходят его цифры. Поле телефона в этом случае показывает «+…» вместо флага.
- Перенос старых заказчиков: один контрагент — то же имя и не другой телефон. «Асан» с двумя разными номерами — два контрагента, номера не теряются. Вид (компания или человек) угадывается по названию (ОсОО, ИП, кавычки, «Строй…»). Телефоны бригадиров приводятся к виду +996… все, включая записанные с пробелами.
- График оплаты закрывается и деньгами, и удержаниями — так же, как считается «заказчик должен»; подсказка «Получил» больше не предлагает удержанную сумму.
- Отчёт заказчику в WhatsApp у объектов «за общую сумму» — этапы договора с их статусом и объёмы без цен.
- На экране «Заказчик и оплата» смена способа оплаты — только с подтверждением, а разбивка, которая не сходится с суммой договора, не сохраняется (долг считается по прежней), об этом пишет красная строка.
- Перевод «суммами ↔ в процентах» больше не меняет суммы: доли хранятся точно, на экране — до десятых.
- «Цены за работы»: разделы фиксируются при открытии экрана, строка с новой ценой не перепрыгивает посреди ввода; каждая цена пишется отдельно (вторая берётся из базы), поэтому быстрый ввод не затирает соседнюю.
- В мастере аванс записывается в кассу только у части «сразу»; объёмы в мастере работ и при частичной приёмке — до трёх знаков после запятой (1,125 т).
